1. Verdict

Les quatre services (Repas, Colis, Emplettes liste libre, Courses express) sont utilisables bout-en-bout côté client et livreur. L’app partenaires ne gère que les restaurants. L’admin est un squelette. Paiements réels, caisse livreur, temps réel, S3, Maps et offline IndexedDB manquent.

Hub 4 services Repas Colis + suivi public Emplettes liste Courses express PWA sans offline Admin vide FedaPay / WS / S3 / Maps

Client

Utilisable : compte téléphone + mot de passe, hub 4 services, catalogue/fiche/panier Repas, suivi (polling), carnet au checkout, Colis (création, tarif, CR, programmation, interdits, suivi + lien public), Emplettes liste libre (budget, remplacements, pointage, décompte), Courses express (description, multi-étapes, tarif, suivi).

Trous pour une ouverture ville : pas d’OTP SMS, pas d’invité, Mobile Money sans FedaPay, pas de WebSocket/push, historique non unifié (/commandes = Repas seulement), pas de recommander / notation / notifs, pas de photo (S3), pas de catalogue Emplettes.

Restaurant

Commandes (polling), acceptation/refus, préparation/prêt, menu, rupture, horaires / fermeture temporaire. Manque : délai d’acceptation, alerte sonore, CA, relevés, WhatsApp de secours.

Commerce partenaire

Type commerce en base. L’app partenaires ne sert que les restaurants. Bloque F-CLI-29 (Emplettes catalogue).

Livreur

Disponibilité, files des 4 services, transitions de statut, OTP Colis (côté client), pointage Emplettes, liens Maps 2 points. Pas de portefeuille, pas de récap journalier, pas d’offline IndexedDB, pas de photo enlèvement/ticket. Les routes / et /mes-courses = Repas, pas Courses express (/courses-express).

Back-office

Aucune route admin. Pas de dispatch auto (RG-14), pas de caisse (RG-03), pas de reversement Colis (RG-04). Zones et taux existent en données seulement.

3. Vulnérabilités

Sain : Prisma paramétré (pas d’injection SQL), pas d’XSS HTML brut, prix Repas recalculés serveur, ownership des commandes, suivi public Colis en liste blanche (id, statut, taille, fragile, dates), register forcé en rôle client, bcrypt 12 rounds.

6. Priorités avant ouverture ville (Repas + Colis)

  1. Durcir auth : rate limit, CORS obligatoire, JWT plus court, rôle relu en base.
  2. OTP Colis obligatoire ; prise Repas atomique ; revalider la zone dans les 4 prises de course.
  3. Projeter GET /restaurants/:id (masquer userId / tauxCommission).
  4. Ne pas ouvrir espèces / contre-remboursement sans portefeuille livreur (RG-02) et un minimum de back-office caisse.

Intégrations hors code : FedaPay, Web Push, WhatsApp/SMS, WebSockets, S3, Google Maps, offline livreur.

Plan d’action associé : vagues P0 (A01–A06) puis P1 (JWT, plafonds, commission, Helmet, PII).
